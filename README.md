# 🎮 Сапёр (Minesweeper) — Оптимизированная версия

Классическая игра Сапёр с поддержкой экстремальных размеров поля до **4100×4100** (16.8 миллионов ячеек).

## ✨ Ключевые оптимизации

### 1. **Виртуализация рендеринга**
- Рендерятся только видимые ячейки + буфер в 5 ячеек
- Поддержка прокрутки для огромных полей
- Плавная работа даже на мобильных устройствах

### 2. **Оптимизированная структура данных**
```typescript
interface OptimizedBoard {
  flags: Uint8Array;        // Битовые флаги (мина/открыта/флаг)
  adjacentMines: Uint8Array; // Количество соседних мин
  totalCells: number;
}
```
- Использование `Uint8Array` вместо массивов объектов
- Битовые операции для хранения состояния ячеек
- Экономия памяти: **~16 МБ** для поля 4100×4100 вместо ~500 МБ

### 3. **Константы вместо магических чисел**
```typescript
export const GAME_CONSTANTS = {
  CELL_SIZE_MIN: 18,
  CELL_SIZE_MAX: 44,
  LONG_PRESS_DURATION: 500,
  AUDIO_VOLUME: { MUSIC: 0.08, ... },
  VIRTUALIZATION: { BUFFER_CELLS: 5, ... },
}
```

### 4. **Уровни сложности**
| Уровень | Размер | Мины | Описание |

| 😊 Лёгкий | 9×9 | 10 | Для новичков |

## 📦 Хранение статистики и рекордов (исправление от 09.10.2026)

### 🔴 Найденный баг
После победы результаты **не сохранялись ни в статистику, ни в таблицу рекордов**.

**Причины:**
1. **Переполнение cookie (основная причина).** Вся история игр сериализовалась
   в один cookie `minesweeper_results`. Cookie жёстко ограничен ~4096 байтами,
   а `encodeURIComponent()` раздувает кириллические имена игроков примерно в 3
   раза. Как только список превышал лимит, браузер **молча** отбрасывал запись:
   `saveGameResult()` не возвращал ошибку, но данные не сохранялись. Эмуляция
   поведения браузера подтвердила: из 60 побед в cookie помещается лишь ~14.
2. **Побочные эффекты внутри updater-функций React.** Вызовы `saveGameResult()`
   находились внутри `setBoard(currentBoard => { ... })`. Такие updater'ы должны
   быть чистыми; при повторном выполнении (dev-режим / StrictMode) одна партия
   записывалась несколько раз, ускоряя переполнение хранилища.

### 🟢 Исправление
- Добавлен модуль `src/utils/storage.ts` — обёртка над **localStorage**
  (лимит ~5 МБ вместо 4 КБ у cookie) с проверкой доступности.
- `cookies.ts`: `saveGameResult()` / `getResults()` теперь пишут и читают полную
  историю в localStorage; в cookie сохраняется компактное «зеркало» последних
  10 записей как фолбэк и для обратной совместимости со старыми данными.
- `Game.tsx`: сохранение результата вынесено из updater-функций `setBoard(...)`
  в единый `useEffect`, реагирующий на переход `gameState` в `'won'`/`'lost'`,
  с защитой от двойной записи одной партии (`savedResultForGameRef`).

## 🔧 Оптимизации для больших полей

1. **Ленивые вычисления** — соседние мины считаются только при размещении
2. **Typed Arrays** — компактное хранение данных
3. **Виртуализация** — рендер только видимых ячеек
4. **Memoization** — мемоизация компонентов через `React.memo`
5. **Event delegation** — делегирование событий для уменьшения listeners
